# Grader Info — Design Spec

## What this builds

A `graderInfo` field on SA and CL questions that stores a model answer / marking guidance, populates `<graderinfo>` in Totara XML exports, and can be bulk-generated by Claude for existing questions with human review via the edit panel.

## Background

The Totara/Moodle XML essay format includes a `<graderinfo>` field that is only visible to markers inside Totara. The app currently exports an empty `<graderinfo>` block. With ~500 existing SA/CL questions lacking model answers, a bulk AI-generate + auto-save workflow is needed, with the edit panel as the human review surface.

---

## Section 1: Data & API

### Database

Add `graderInfo String?` to the `Question` model in `prisma/schema.prisma`:

```prisma
model Question {
  ...
  graderInfo   String?
  ...
}
```

Run `prisma db push` (or `prisma migrate dev`) to apply.

### PATCH `/api/questions/[id]`

Add `graderInfo` to the allowed update fields. No other changes to this route.

### POST `/api/questions/[id]/generate-grader-info`

- Reads the question from DB (type, questionText, name, section)
- Rejects with 400 if type is not SA or CL
- Calls Claude (`claude-opus-4-7`) using the appropriate prompt builder
- Saves the result to `question.graderInfo` via Prisma
- Returns `{ graderInfo: string }`

### `src/lib/prompts/generate-grader-info.ts`

Two exported functions:

- `buildGenerateGraderInfoSAPrompt({ questionText, sectionText? })` — instructs Claude to write an Excellence-level model answer covering all three SA criteria (Concept, Application, Evidential Sufficiency). Output is plain text.
- `buildGenerateGraderInfoCLPrompt({ questionText, sectionText? })` — instructs Claude to write an Excellence-level model answer covering all five CL criteria (Legislation, Core Concepts, Case Law, Defences, Evidential Sufficiency) plus the topic hints. Output is plain text.

Both prompts inject the verbatim marking matrix from `matrices.ts`.

## Section 2: Export

### `src/lib/export.ts`

Add `graderInfo: string | null` to `ExportQuestion`.

In `toTotaraXml`, for SA and CL questions:

```xml
<graderinfo format="html">
  <text><![CDATA[graderInfo content or empty]]></text>
</graderinfo>
```

MC and PR questions do not get a `<graderinfo>` block (MC is auto-marked; PR is out of scope).

If `graderInfo` is null or empty, emit an empty `<graderinfo>` block (preserving current behaviour for questions that haven't been generated yet).

## Section 3: UI

### Library page (`src/app/library/page.tsx`)

Add `graderInfo` to the Prisma `select` block so it flows through to `LibraryClient`.

### `ExportQuestion` / question type

Add `graderInfo: string | null` alongside the other fields passed to `LibraryClient`.

### Bulk toolbar (`LibraryClient.tsx`)

- "Generate grader info" button appears when ≥1 SA or CL question is selected
- Fires `POST /api/questions/[id]/generate-grader-info` for each SA/CL question in the selection sequentially
- MC and PR questions in the selection are silently skipped
- Progress counter: "Generating X of Y…" (same pattern as existing bulk topic assign)
- Updates local question state as each response comes back
- Button is disabled while generation is running

### Edit panel — view mode

- If `graderInfo` is populated, show a "Grader info" section below the question text, collapsed by default
- Expand/collapse toggle

### Edit panel — edit mode

- Add a `graderInfo` textarea below the `questionText` textarea
- Saves alongside other fields on "Save changes"

---

## Constraints

- Generation only supported for SA and CL (400 for other types)
- Plain text output from Claude (not HTML); exported wrapped in `<![CDATA[...]]>`
- No streaming — each generate call is a normal POST that resolves when Claude finishes
- No queue or background job — bulk generate runs sequentially in the browser, same pattern as bulk topic assign
